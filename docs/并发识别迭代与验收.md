# 并发识别迭代与验收

实施日期：2026-10-29。

## 行为变更

240 秒与 20 分钟改为执行预期，服务与真实测试不因超过预期停止后备识别。识别函数保留显式有限 budget 参数供旧调用者和协议单元测试使用；产品工作线程传入无限阶段额度。每次模型请求仍有独立超时，不受其他合同排队时间影响。

前台、后备工作线程默认各两个；通过同一 worker_threads 工厂启动，服务与测试一致。底层请求池按队列隔离，默认各两个真实请求槽位。请求超时后，仍在运行的网络调用占用原槽位；池内排队不会消耗实际请求等待额度。暂未引入分布式队列，仍要求单服务进程。

任务领取通过 BEGIN IMMEDIATE；模型调用在事务外。新增活动任务部分唯一索引，重复创建活动任务会被数据库拒绝。旧库若存在重复活动任务，索引创建会明确失败，需先核对任务记录，不静默删除。回写保留文档版本、状态及人工草稿保护。

服务每次启动创建独立停止事件，停机后停止领取与新请求，短暂等待工作线程；执行中请求不会因为关闭线程而被错误宣布取消。强制退出后的执行中任务重启标记 interrupted，不自动重复付费请求。

字段规范化处理乙方标签、证件号与电话标签粘连、重复日期及平方米单位指数；原始值与文本继续保留。不同金额、地址、编号和勾选状态不通过猜测消除。合同编号标点的来源误识别、计租勾选缺失仍需在真实复测中披露。

## 工程验证

验证覆盖两线程同时领取不同任务、旧合同不因时间过长失败、旧后备 deadline 不阻断、四路请求同时执行、请求池等待不消耗请求超时、取消后不发请求，以及原有人工编辑保护、重启恢复与识别协议测试。

完整 pytest 输出保存在 runs/iteration-engineering-tests-20261029.txt。相关静态检查针对本轮涉及文件执行；既有其他改动不在本轮重写。

## 实跑设计

工作目录同时存在其他开发变更，因此正式实验使用 runs/iteration-20261029-frozen 中冻结的 app、scripts、config，哈希见 frozen-sha256.json。三轮顺序执行：同源码关闭字段清洗的 1＋1、同设置的 2＋2、开启字段清洗的 2＋2。每轮均为 LX-001 至 LX-010 的新导入与新数据库，真实调用，不用答案补值；终态之后离线对照标准答案。

初步 runs/iteration-20261029-baseline 用于运行检查，不作为严格并发因果对照。原先受硬截止影响的 311.545 秒仅作历史记录。正式实验每种设置仅一轮，供应商负载和返回差异仍会影响耗时；报告应同时比较请求数、未知结果和字段结果，不仅比较秒数。

结果见后续生成的复测报告。

# 比赛修复：识别恢复与证据准入独立验收

验收范围：短页号映射、模型响应不完整时的留证、主路径失败后的逐页恢复、跨进程缓存、未知请求重发门禁、晚响应隔离、进程内全局并发上限，以及批量准入的证据规则。

全部输入为明确合成数据，供应商访问使用 HTTP MockTransport；无真实云调用、无产品库写入、无真人核验或评分提分结论。

## 检查方式

```sh
.venv/bin/python -m pytest -q tests/test_competition_recovery.py
.venv/bin/python -m ruff check tests/test_competition_recovery.py
```

测试文件为独立设计的行为反例，包含两次独立 Python 进程、不同 `PYTHONHASHSEED` 的恢复验证；不只在同一进程里重复调用。

## 首轮结果与修复要求

首轮 25 项场景中，21 项通过、4 项失败；测试文件 Ruff 通过。

1. **未知请求确认重发仍被拒绝。** ReadTimeout 被保存为 `status=failed` 且 `outcome_unknown=true`，只传 `retry_unknown=true` 时仍受 `retry_failed=false` 拦截。未知请求的明确确认应独立生效；已知失败重试不得隐式解锁未知请求。
2. **布尔值被当作坐标。** `bbox=[false,0.1,true,0.5]` 被解析成原图 `[0,20,200,100]`，制造了有效区域。坐标需拒绝 bool，并要求有限数值和合法范围。
3. **百度任务查询失败丢失未知状态。** 已取得 `task_id` 后查询耗尽预算，被当成已知失败且任务号丢失。应保留 `task_id` 与未知结果标记，避免普通失败重试重新提交同一任务。
4. **跨进程缓存不稳定。** 逐页备用请求指纹拼入由 set 迭代产生的字段列表。进程哈希种子改变后，已完成 secondary/context 请求被重发。构造请求和指纹前应统一排序字段。

以上问题由实现者修复；独立验收者未修改产品源代码。

## 修复后独立复验

**ACCEPTED（仅限本报告声明的工程边界）**。再次运行相同独立反例测试：`25 passed in 0.49s`。四个首轮反例均通过，包括跨进程恢复不会重发已完成的辅助请求、百度任务号保留、未知请求单独确认重发和布尔坐标拒绝。测试进程正常退出，无遗留测试请求或子进程。

## 已验证行为

- 页号 0、负数、越界数、bool、浮点和字符串均不作为合法短页号；仅隔离对应候选，有效候选保留。
- 长页 ID 只接受当前文书的精确旧值，跨文书引用和短页号/旧 ID 冲突不猜测修复。
- 截断结束与非法 JSON 的原响应落盘留证，不进入候选。
- 多页主请求读取超时后，单页结构化恢复能继续；已完成页面再次恢复不重发。
- 普通失败重试不会自动重发结果未知请求。
- 本地等待预算到期后，晚响应不会写入候选缓存或改变已落盘未知状态。
- 四份文档同时申请请求时，进程内实际执行请求最多两个。
- 有有效主证据时，一致的无框、无分数辅助识别不会污染准入；全部缺主证据、真实低分、冲突、跨文书引用和涂改前候选仍被阻塞。
- 全角数、等价日期比较归一化后可一致，原始候选不被改写。
- 变更协议不被强制要求租期、面积、年租金等不适用字段。

## 第二轮：两阶段调度与 OCR 协议补充验收

新增四项行为场景：已成功读取的空白页不因全局字段缺失而重复调用备用路径；实际读取失败的页即使其他页字段已齐也必须获得一次有效读取；阿里 OCR 纯坐标响应留证拒收及图片在任务提示前的顺序；结构化提示不把缺省置信度诱导成零分。

首轮补充结果：28 项通过、1 项失败。失败反例是第二页主请求超时，但第一页获得双路径全字段后，第二页备用读取被全局字段覆盖条件跳过。已交实现者修复。该条件与“已成功读取、没有额外字段的空白页无需重复识别”不同；未读页仍可能包含签章或批注。

补充修复后复验：**29 项全部通过（0.55 秒）**，包括失败页必须恢复及重跑不重复发送已完成请求。第二轮工程验收结论为 **ACCEPTED**；未扩大真人、真实供应商或多进程限流的验收范围。

## 第三轮：完整双路径冲突、布局框与类型证据

追加验证：完整双路径已返回时，真实字段冲突或低分直接交人工，不调用第三模型投票；原件疑点 warnings 仍阻塞批量准入；百度布局分数不作为文字置信度；已验证坐标帧只映射供应商整块区域；坐标帧不匹配或发生旋转时不映射。

本轮发现两类类型证据问题：新签标题的 `raw_text` 使用说明词而非实际标题，以及正文将来可能签订“续期/变更协议”的条款被当成当前文件类型。前者已经实现者修复并通过；后者在条款 OCR 和新布局解析器均有反例，已交回修复。当前 38 项中 36 项通过，剩余两项为两个解析器对同一将来条款的错误分类。

第三轮修复后复验：**38 项全部通过（0.59 秒）**，Ruff 与差异空白检查通过。当前合同类型取实际标题或明确“本合同为/系续签”的原文说明，将来可能续期或签订变更协议的通用条款不再改变当前类型。最终独立工程验收结论为 **ACCEPTED**，仅限本报告声明的恢复、协议和证据准入范围。

本报告覆盖的代码复验发生在真实全量运行冻结之后；真实运行的准确率、耗时和字段输出应以对应运行的代码哈希、模型与提示版本解释，不得把后续修复自动算进已冻结运行成绩。

## 第四轮：已保存人工草稿与迟到识别结果

独立只读检查 `worker_once` 的两道保护：执行后备识别前发现同版本人工草稿即取消任务；结果回写在 `BEGIN IMMEDIATE` 事务中通过 `NOT EXISTS` 同版本草稿条件原子拒绝，因此草稿保存与回写竞争不会仅靠先前检查决定。被拒绝的主识别任务会将仍为 recognizing 的同版本文书转回 needs_human，不增加版本、不隐藏草稿。

复用实现者新增的两个有意义回归并实际执行：保存草稿后后备不再调用，以及在阻塞的主识别期间保存草稿后迟到结果不覆盖。结果为 **2 passed in 0.45s**。结合对事务条件的独立检查，该持久化边界结论为 **ACCEPTED**。未修改产品或测试文件，无遗留测试线程调用。

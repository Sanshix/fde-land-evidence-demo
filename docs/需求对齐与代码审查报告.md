# 国有土地租赁系统：需求对齐与代码审查报告

Oct 28, 2026 · @Max

对照赛题需求说明、核算口径、使用说明和 10 月 27 日甲方访谈逐条核对代码。原代码的证据链与留痕做得扎实，但业务闭环缺口较大：变更协议无法入库、缴费候选漏掉大多数记录、13 类问题缺 5 类、另 3 类判定不全、提醒/统计/税务留存/合同生成缺失，核算有 4 处与口径或标准答案不符，部署到服务器后无法写入。以上均已修复，修复后用已确认要素走完整流程，出题方评分脚本得 96.2 分（按标准答案的取整方式为 100 分）。

规则引擎现已与口径对齐；识别环节仍是短板，直接决定现场补档（40 分）的成败。

## 审查发现的缺陷与修复

共 22 处，全部已修复并有测试覆盖。“高”指会直接导致金额错误、无法入库或系统不可用。

| 严重度 | 位置 | 问题 | 后果 |
| --- | --- | --- | --- |
| 高 | business.py `SAMPLES` | 练习集路径写死为 `../练习集` | 在你们现有目录结构下服务启动即报错；评测集也无法切换 |
| 高 | main.py `actor()` | 写操作只接受 Origin 为 127.0.0.1/localhost:8765 | 部署到服务器后浏览器里所有提交均 403 |
| 高 | providers.py `approved_input` | 只放行练习集原图哈希 | 评测集和现场补档永远不会送模型，只能全手录 |
| 高 | providers.py `model_profile` | 强制 HTTPS + 公网域名密钥绑定 | 无法切换到内网 vLLM/Ollama 开源模型 |
| 高 | domain.py `validate_fields` | 变更协议也要求面积、租期、计租方式 | LX-002/035 无法确认，催缴对象和“未办变更”判定失真 |
| 高 | business.py `suggest` | 缴费只按坐落原文全等匹配，且界面无其他勾选途径 | “繁荣路258”“09-03-0116”和宗地栏空白的记录全部漏掉，欠缴严重偏大 |
| 高 | domain.py 归集 | 未注明年度的缴款只冲抵到缴费当年 | LX-009 补缴“2023 至 2025”当成多缴，欠缴年度错 |
| 高 | domain.py 归集 | 缴费日期晚于基准日的缴款被静默丢弃 | LX-031/032/040/047 欠缴偏大 220–458 元 |
| 高 | business.py `parcel_key` | 未登记宗地用地号原文作键 | LX-033 新号与 LX-038/046 旧号拆成两宗 |
| 高 | business.py 归宗 | 不识别“原合同编号”链 | LX-020 宗地号错一位，与变更协议 LX-002 分开，误报“登记无对应” |
| 高 | main.py `retry` | 识别进行中允许重试 | 版本号被抬高、结果被丢弃，文书永久停在“等待处理” |
| 中 | app.js 阻断项下拉 | `<option>` 标签写错，“已有可核实证据”没有 value | 有阻断项的文书只能选“排除”才能确认 |
| 中 | outputs.py 催缴通知书 | 合计行占位符未替换；可选段落始终保留；大写写“待人工填写” | 生成的通知书不能直接使用 |
| 中 | main.py 短信草稿 | 未按短信模板，缺欠缴年度、期限、地点 | 产权人看不懂欠哪几年、到哪里缴（评委专门看这点） |
| 中 | business.py 问题清单 | 缺 5 类判定；电话缺失不报、宗地号不符不报、缴费只查重复票据 | LX-030 等漏报，问题清单得分低 |
| 中 | domain.py `dec` | `decimal.InvalidOperation` 不是 `ValueError` | 源表金额为空时预览返回 500 而不是业务提示 |
| 中 | domain.py `upper_money` | 不足一元的“伍角”“伍分”报未知字符 | 这类金额无法核算 |
| 中 | domain.py 所属年度 | “2003至2005”会被当成 2003 年 | 多年补缴全记入一年并计为多缴 |
| 中 | governance.py 引用校验 | “有无宗地图/缺页”等文书属性也强制引用页 | 界面确认被拦 |
| 低 | intake.py 图片 | 未按 EXIF 方向摆正 | 手机拍照件侧躺，识别与核对变差 |
| 低 | main.py 备份 | 备份写到代码目录 `runs/` | 服务器代码目录只读时备份失败 |
| 低 | app.js `api()` | 非 JSON 错误响应解析崩溃 | 提示变成乱码报错 |

另在若干细节上做了加固：日历文件转义、登记面积为空时不崩溃、重叠合同整段落入旧合同时不产生无效租期。

## 需拍板的口径问题

以下是口径没写清、或与标准答案不一致的地方，代码已按“当前做法”实现并可配置，路演时可作为存疑判断的理由讲。

| 事项 | 口径/答案怎么说 | 当前做法 | 影响 |
| --- | --- | --- | --- |
| 取整 | 口径写“四舍五入到分”；标准答案用浮点 `round()`，恰好 x.xx5 时舍去（如 1999.125→1999.12） | 默认按口径；`FDE_ROUNDING=answer_key` 复现答案 | 5 宗差 0.01–0.07 元；评分容差 0.01，其中 3 宗失分（约 3.8 分）。现场评委按答案核对，由你们决定路演用哪种 |
| 缴费日期晚于基准日 | 口径未写；答案计入实缴（2026-11 的 4 笔） | 计入并在归集明细注明 | 与答案一致 |
| 注明年度的多缴 | 口径七（二）；答案逐年“实缴”含多缴、欠缴记 0 | 同答案 | LX-026 2022 年显示一致 |
| 同票据号金额不同 | 口径只说重复登记计一次 | 按金额较大者暂计（对产权人有利）并列存疑 | 练习集未出现，防范评测集 |
| 税务“本期应缴” | 字段说明未定义；模板示例为第二季度等于年租金 | 缴纳期限 6 月 30 日所在季度计当年应缴，其余季度为 0 | 待税务部门确认 |
| 合同缺页 | 答案由人看原件判定（缺第 2 页签章页） | 制式合同 3 页；页数少且有宗地图时提示“可能缺签章页”，人工确认 | 练习集 3/3 命中 |
| 宗地栏空白的缴款 | 口径未写归集依据 | 缴款人与本宗承租人/权利人同名时列为“弱依据”候选 | 练习集 414 条归集全对；评测集遇同名多宗须人核 |
| 宗地号对不上但坐落唯一匹配 | 口径列为“坐落或宗地号与登记不一致” | 按坐落归到登记单元并报该问题 | LX-020 正确 |

## 尚未完成与剩余风险

最大的风险是识别：规则侧已经能拿满分，但目前没有任何一个模型在练习集上跑出可用的实测结果。

1. **视觉大模型未实测。** 仓库记录的硅基流动、阿里、百度三次实连均超时。本机 PP-OCRv4（RapidOCR）实测 50 份关键字段全对 0 份：签订日期 84%、宗地号 80%、起止日期约 40%、面积 30%、坐落 0%。网络恢复后先用 `config/providers.competition.json` 跑练习集，再定批量确认门槛。
   - 现场补档 20 分钟：识别单线程、每份预算 180 秒，10 份以上可能超时，建议先演练。
2. **批量确认门槛未经真实数据校准。** 当前要求关键字段由两条独立路径给出同一值、无任何风险提示。门槛偏严会把大多数送人工（每份 0.5 分），偏松每错一份扣 1 分。
3. **交付文档不在仓库。** SOP、3,000 份人员与天数测算、经办人员操作手册、年度费用估算都还没有；README 已重写了部署与运维部分。
4. **离线包不含 Python 运行时。** 目标机须预装 Python 3.12；本机 OCR 的 wheel 在 `requirements-local-ocr.in`，构建时需一并下载。
5. **材料分组。** ZIP 按文件夹或“档案号\_页序”分组；一个 PDF 里有多份文书不会自动拆分，只能在复核页“并入所选文书”手工纠正。
6. **安全。** 本机演示模式仍靠请求头切换角色；服务器模式为 HTTP Basic，需内网或 TLS 入口。ZIP 大小检查信任压缩包头声明的尺寸（低风险）。
